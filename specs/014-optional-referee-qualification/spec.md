# Feature Specification: 審判資格なしメンバー登録

**Feature Branch**: `014-optional-referee-qualification`  
**Created**: 2026-06-11  
**Status**: Draft  
**Input**: 審判資格を持たない人がコミュニティの運営者となる場合もあると考えます。審判資格無しでメンバー登録できるよう改善したい

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 運営者として審判資格なしでプロフィール登録 (Priority: P1)

サッカーチームの代表者や保護者など、審判ライセンスを持たないコミュニティ運営者が、ライセンス情報を入力せずにプロフィールを登録できる。

**Why this priority**: 現在は審判ライセンスが必須入力のため、資格を持たない運営者はプロフィール登録自体が完了できない。これがブロッカーとなっており、最優先で解消すべき課題。

**Independent Test**: 審判ライセンスを空欄のままプロフィールを保存し、コミュニティへの参加申請まで完了できることを確認。

**Acceptance Scenarios**:

1. **Given** 未登録ユーザーが初回プロフィール入力画面を開いている、**When** 審判ライセンスを選択せずに表示名・地域のみ入力して保存する、**Then** プロフィールが正常に保存される
2. **Given** ライセンスなしでプロフィールを保存した、**When** コミュニティ一覧を開いて参加申請ボタンを押す、**Then** 申請が受け付けられ「審査中」ステータスになる
3. **Given** ライセンスなしで登録したユーザーが審判ライセンスを後から取得した、**When** プロフィール編集でライセンスを追加する、**Then** ライセンス情報が更新されて以後審判としても活動できる

---

### User Story 2 - 管理者がライセンス状況を確認しながらメンバーを承認 (Priority: P2)

コミュニティ管理者が、参加申請してきたユーザーのライセンス保有状況をメンバー管理画面で確認しながら承認・却下できる。審判ライセンスなしのメンバーは承認後も自動的にアサイン候補には含まれない。

**Why this priority**: 管理者が申請者のライセンス有無を把握した上で承認判断できることが重要。ロール自動変更は意図しない管理権限付与を招くリスクがあるため行わない。アサイン候補の除外はプロフィールデータ（担当役割の未設定）によって保証される。

**Independent Test**: 審判資格なしのユーザーが申請した際、管理者画面でライセンスなしが識別でき、承認後もアサイン候補に現れないことを確認。

**Acceptance Scenarios**:

1. **Given** 審判資格なしのユーザーがコミュニティに参加申請した、**When** 管理者がメンバー管理画面を開く、**Then** 申請者の詳細にライセンスが「なし」と表示される
2. **Given** ライセンスなしのユーザーが承認された、**When** 試合のアサイン候補一覧を表示する、**Then** そのメンバーはアサイン候補に含まれない
3. **Given** コミュニティにライセンスありメンバーとなしメンバーが混在している、**When** 管理者がメンバー一覧を表示する、**Then** ライセンス欄でそれぞれが識別できる

---

### User Story 3 - 運営者ユーザーに最適化されたプロフィール画面 (Priority: P3)

審判資格なしで登録したユーザーのプロフィール画面では、審判特有の項目（担当役割・対応年代）が省略され、入力負荷が軽減される。

**Why this priority**: 入力不要な項目が表示されているとUXが悪化するが、P1・P2が完了していれば利用は開始できるため優先度は低い。

**Independent Test**: ライセンスなしで登録したユーザーのプロフィール編集画面に審判特有の項目が表示されないことを確認。

**Acceptance Scenarios**:

1. **Given** 審判ライセンスなしでプロフィール登録したユーザーがプロフィール編集画面を開く、**When** 画面を確認する、**Then** 「担当役割」「対応年代」フィールドが表示されない
2. **Given** 運営者として登録したユーザーが後から審判ライセンスを登録する、**When** ライセンスを選択して保存する、**Then** 「担当役割」「対応年代」フィールドが表示され入力できるようになる

---

### Edge Cases

- 既存の審判メンバー（ライセンスあり）のプロフィールは変更なしで引き続き動作する
- ライセンスなしのユーザーがアサイン候補として検索された場合はリストに表示されない
- ライセンスなしのユーザーが参加申請時に、申請先コミュニティが「審判のみ受付」ポリシーを持つ場合の扱い（現時点ではコミュニティ側ポリシー設定機能がないため、全申請を受け付けて管理者が承認判断する）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: プロフィール登録時に審判ライセンスの入力を任意（オプション）にする
- **FR-002**: プロフィール登録時に「担当役割」「対応年代」の選択をライセンスあり時のみ必須とし、ライセンスなし時は任意または非表示にする
- **FR-003**: コミュニティ参加申請時のロールは変更せず、既存通りすべて `referee` として登録する
- **FR-004**: 管理者のメンバー管理画面でメンバーのライセンス有無を識別できる（ライセンスなしの場合「なし」と表示）
- **FR-005**: 担当役割（`role_type`）が未設定のメンバーはアサイン候補から除外される（既存の候補フィルタで実現済み）
- **FR-006**: 審判ライセンスを持つユーザーは既存通りの操作フローで参加申請・アサイン候補登録できる
- **FR-007**: ライセンスなしで登録したユーザーが後からライセンスと担当役割を追加できる（プロフィール編集）

### Key Entities

- **ユーザープロフィール**: `license_level`（任意）、`role_type`（任意・ライセンスあり時のみ必須）、`age_groups`（任意・ライセンスあり時のみ必須）、`display_name`・`region`（必須）
- **コミュニティメンバー**: 申請時のロールは常に `referee`。`organizer` / `manager` ロールは管理者が手動で付与する

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 審判ライセンスなしのユーザーが、プロフィール登録からコミュニティ参加申請まで3分以内に完了できる
- **SC-002**: 既存の審判ユーザーのプロフィール登録・コミュニティ参加フローが変更前と同じ手順で動作する（リグレッションゼロ）
- **SC-003**: 管理者がメンバー管理画面でライセンス有無を一目で識別できる（追加のフィルタ・ソートなしで）
- **SC-004**: ライセンスなし・担当役割未設定のメンバーがアサイン候補一覧に表示されない（誤アサインゼロ）

## Assumptions

- コミュニティ参加申請時のロールはライセンス有無にかかわらず常に `referee`。ロール自動判定は行わない（意図しない管理権限付与を防ぐため）
- `organizer` / `manager` ロールは現時点では管理者が手動で付与するものとし、今回の申請フローには含めない
- 審判ライセンスなしのユーザーは試合アサイン通知・候補一覧の対象外とする
- 電話番号・本名はアサイン確定時の開示情報のため、運営者には任意項目のままとする
- モバイルブラウザ（LINE内ブラウザを含む）での動作を想定する
