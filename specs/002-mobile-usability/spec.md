# Feature Specification: スマートフォン対応ユーザビリティ改善

**Feature Branch**: `002-mobile-usability`  
**Created**: 2026-06-05  
**Status**: Draft  
**Input**: User description: "スマホの画面から各画面のレイアウトが崩れない、テーマによって表示が乱れないなど、スマホからのUsabilityを改善したいです。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 審判がモバイルから主要画面を快適に操作できる (Priority: P1)

審判ユーザーがスマートフォンからプロフィール・空き日程・参加申請・担当履歴の各画面にアクセスしたとき、レイアウトが崩れず、ボタンやフォームが正しく操作できる。

**Why this priority**: 審判はLINE経由でアプリにアクセスするため、スマートフォンが主要デバイスである。レイアウト崩れは基本的な利用不能を意味し、最も優先度が高い。

**Independent Test**: スマートフォン実機（またはブラウザの375px幅エミュレーション）でログイン後、プロフィール→空き日程→担当履歴の順に画面遷移し、すべての操作が完了できることを確認する。

**Acceptance Scenarios**:

1. **Given** スマートフォンで審判がプロフィール画面を開いたとき、**When** 画面を縦向きで表示したとき、**Then** テキスト・フォーム・ボタンが画面幅内に収まり、横スクロールが発生しない
2. **Given** スマートフォンで審判が空き日程カレンダーを表示したとき、**When** カレンダーを操作しようとしたとき、**Then** カレンダーが画面幅内に収まりタップで日付選択ができる
3. **Given** スマートフォンで審判が担当履歴画面を開いたとき、**When** 一覧を閲覧したとき、**Then** 各行の情報が省略・重なりなく読める
4. **Given** スマートフォンで審判が参加申請（join）画面を開いたとき、**When** フォームを入力・送信しようとしたとき、**Then** 入力欄とボタンが正しく表示されタップ操作できる

---

### User Story 2 - 管理者がモバイルから試合・メンバー管理を確認できる (Priority: P2)

管理者ユーザーがスマートフォンから試合一覧・試合詳細・アサイン状況・メンバー承認の各管理画面にアクセスしたとき、情報が読み取れ、基本的な操作が行える。

**Why this priority**: 管理者は主にPCを使うが、外出先でスマートフォンから状況確認やアサイン操作を行う需要がある。完全な操作性よりも情報の視認性が重要。

**Independent Test**: スマートフォン実機（またはブラウザの375px幅エミュレーション）で管理者ログイン後、試合一覧→試合詳細→アサイン画面を閲覧し、主要情報（試合日時・場所・審判名）が読み取れることを確認する。

**Acceptance Scenarios**:

1. **Given** スマートフォンで管理者が試合一覧（/admin/matches）を開いたとき、**When** 一覧を閲覧したとき、**Then** 試合日時・場所・ステータスが横スクロールなしで読める
2. **Given** スマートフォンで管理者がアサイン画面を開いたとき、**When** 候補審判リストを確認したとき、**Then** 各候補の情報が重ならず表示される
3. **Given** スマートフォンで管理者がメンバー承認画面を開いたとき、**When** 承認待ちリストを確認したとき、**Then** 承認・却下ボタンがタップできるサイズで表示される

---

### User Story 3 - テーマ切り替え時も表示が乱れない (Priority: P3)

ユーザーのデバイスがライトモード・ダークモードのどちらに設定されていても、すべての画面でテキスト・背景・ボタンの色が適切に表示され、視認性が確保される。

**Why this priority**: OSのテーマ設定に応じた自動切り替えが正しく機能しないと、一部のユーザーでテキストが読めない状態になりうる。ただし既存の機能追加が主目的のため優先度はP3。

**Independent Test**: ブラウザの開発者ツールでprefers-color-schemeをdark/lightに切り替え、ログイン画面・プロフィール画面・管理画面を確認し、すべてのテキストが読めることを確認する。

**Acceptance Scenarios**:

1. **Given** デバイスがダークモードに設定されているとき、**When** 任意の画面を開いたとき、**Then** すべてのテキストが背景と十分なコントラストで表示される
2. **Given** デバイスがライトモードに設定されているとき、**When** 任意の画面を開いたとき、**Then** すべてのテキストが背景と十分なコントラストで表示される
3. **Given** テーマがいずれかに設定されているとき、**When** ボタン・バッジ・ステータス表示を確認したとき、**Then** 色が意図した意味（例：エラー＝赤、成功＝緑）で読み取れる

---

### Edge Cases

- 非常に小さい画面（幅320px、古いiPhone SE相当）でレイアウトが完全に崩れないか？
- 長いテキスト（審判氏名・場所名）が入力されたとき、レイアウトを崩さず省略または折り返されるか？
- テーブル・カレンダーなど横幅が大きくなりがちなコンポーネントで、意図しない横スクロールが発生しないか？
- フォームのキーボード表示時に入力欄が画面外に追い出されないか？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: すべての審判向け画面（プロフィール・空き日程・担当履歴・参加申請・ログイン）は、幅375px以上のスマートフォン画面で横スクロールなしに表示されなければならない
- **FR-002**: すべての管理者向け画面（試合一覧・試合詳細・アサイン・メンバー承認）は、幅375px以上のスマートフォン画面で主要情報が読み取れなければならない
- **FR-003**: 操作可能なすべてのボタン・リンク・入力要素のタップ領域は、縦横ともに44px以上でなければならない
- **FR-004**: ライトモード・ダークモードの両方で、すべての画面のテキストと背景のコントラスト比はWCAG AA基準（通常テキスト4.5:1以上、大テキスト3:1以上）を満たさなければならない
- **FR-005**: 空き日程カレンダーは、スマートフォン画面幅（375px）内に収まり、タップで日付選択ができなければならない
- **FR-006**: 試合一覧・候補者リスト・メンバー一覧などのテーブル形式の表示は、モバイル画面で情報が省略または折り返されて読みやすく表示されなければならない
- **FR-007**: 幅320px（最小サポート幅）でも、ナビゲーションとコンテンツの基本的な視認性が維持されなければならない
- **FR-008**: フォーム入力時にモバイルキーボードが表示されても、入力中の欄がスクロールで画面内に収まらなければならない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 審判向け全4画面（プロフィール・空き日程・担当履歴・参加申請）において、幅375pxでのレンダリングで横スクロールバーが発生しない
- **SC-002**: 管理者向け全4画面（試合一覧・試合詳細・アサイン・メンバー承認）において、幅375pxで試合日時・場所・担当者名などの主要情報が視認できる
- **SC-003**: 全画面のすべての操作可能要素（ボタン・リンク）のタップ領域が44×44px以上である
- **SC-004**: ライト・ダーク両テーマで全画面の本文テキストのコントラスト比がWCAG AA基準（4.5:1）以上である
- **SC-005**: 審判ユーザーがスマートフォンからプロフィール確認→空き日程登録→担当履歴確認の主要フローを5分以内に完了できる
- **SC-006**: 管理者ユーザーがスマートフォンから試合一覧閲覧→アサイン状況確認のフローを3分以内に完了できる

## Assumptions

- 対象ブラウザはiOS Safari・Android Chromeの最新バージョン（デスクトップブラウザのモバイルエミュレーションでも検証可能）
- 最小サポート画面幅は320px（iPhone SE 第1世代相当）、主要ターゲットは375px以上
- 横向き（ランドスケープ）表示は必須要件ではなく、縦向き（ポートレート）を主要ターゲットとする
- 既存のTailwind CSSによるスタイリング体系は維持し、大幅なデザイン刷新は行わない
- 管理者向け画面はモバイルでの「閲覧・確認」を主目的とし、すべての管理操作がモバイルで完結することは必須としない
- ダークモード対応はOSの`prefers-color-scheme`に応じた自動切り替えを前提とし、手動テーマ切り替えUIは対象外
- アクセシビリティ基準はWCAG 2.1 AAレベルをベースラインとする
