# Feature Specification: プロフィール選択項目のJFA準拠化

**Feature Branch**: `009-profile-jfa-options`  
**Created**: 2026-06-09  
**Status**: Draft  
**Input**: User description: "プロフィール登録の選択項目をJFA審判ライセンス・登録種別に準拠して見直す。審判ライセンスをS級〜4級からJFA正式区分の1〜4級へ修正（S級はコーチライセンスであるため除外）。対応年代をU12/U15/U18/Seniorから第4種(U-12)・第3種(U-15)・第2種(U-18)・第1種(大学・社会人)へ変更する。女子・シニアカテゴリは追加しない。地域に根ざしたコミュニティ向けの審判マッチングサービス。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 審判員が正確なライセンスと対応年代を登録できる (Priority: P1)

審判員がプロフィールを新規登録または更新する際、JFA公式の審判ライセンス区分（1〜4級）と登録種別（第4種〜第1種）から自分の情報を正確に選択して登録できる。

**Why this priority**: プロフィール情報の正確性がマッチング品質の根幹。誤ったライセンス区分（S級）が選択肢にあることで、実態と異なるプロフィール登録が発生するリスクを排除する必要がある。

**Independent Test**: 審判員としてプロフィール登録画面を開き、ライセンスに「1級〜4級」のみが表示され、年代に「第4種(U-12)〜第1種(大学・社会人)」が表示されることを確認することで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 審判員がプロフィール登録フォームを開いている, **When** ライセンス選択欄を確認する, **Then** 「1級」「2級」「3級」「4級」の4種類のみが選択肢として表示される（「S級」は含まれない）
2. **Given** 審判員がプロフィール登録フォームを開いている, **When** 対応年代の選択肢を確認する, **Then** 「第4種(U-12)」「第3種(U-15)」「第2種(U-18)」「第1種(大学・社会人)」の4種別のみが表示される
3. **Given** 審判員が各選択肢を選択する, **When** フォームを保存する, **Then** 選択した値が正しく登録・反映される
4. **Given** 審判員がライセンスまたは対応年代を未選択のまま, **When** フォームを保存しようとする, **Then** 必須入力エラーが表示され保存されない

---

### User Story 2 - 運営者が正確な種別情報で審判を検索・確認できる (Priority: P2)

運営者が審判を募集・検索する際、または候補者一覧を確認する際に、JFA種別に基づいた正確な年代情報が表示される。

**Why this priority**: 運営者がマッチングに使う年代フィルターとラベルがJFA標準と揃っていることで、実務上の誤解やミスマッチを防ぐ。

**Independent Test**: 運営者として候補者一覧を開き、各審判の対応年代が「第N種(U-XX)」形式で表示されていることを確認することで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 審判員が新しい種別で対応年代を登録済みである, **When** 運営者が候補者一覧を確認する, **Then** 審判員の対応年代がJFA種別表記（例: 第4種(U-12)）で表示される
2. **Given** 運営者が試合を登録する, **When** 対象年代を選択する, **Then** 「第4種(U-12)」〜「第1種(大学・社会人)」の4種別から選択できる

---

### User Story 3 - 既存ユーザーのプロフィールが新選択体系と整合する (Priority: P3)

既に旧形式（U12/U15/U18/Senior、S級）でプロフィールを登録済みの審判員が、システム更新後も正常にプロフィールを参照・編集できる。

**Why this priority**: 既存ユーザーのデータ整合性を保つことで、更新後のサービス継続性を確保する。

**Independent Test**: 旧形式データを持つユーザーとしてログインし、プロフィール編集画面を開いてエラーなく表示・保存できることで単独テスト可能。

**Acceptance Scenarios**:

1. **Given** 旧形式の年代データ（U12等）が登録されているユーザーが存在する, **When** そのユーザーがプロフィール編集画面を開く, **Then** エラーなく画面が表示され、新しい選択肢で再登録できる
2. **Given** システムが新しい選択体系に更新された後, **When** 旧データを持つユーザーが他の情報を変更して保存する, **Then** 対応年代・ライセンスも新しい選択肢で保存される

---

### Edge Cases

- 「S級」を選択済みの既存ユーザーが編集画面を開いた場合の表示はどうなるか？
- 旧年代値（U12等）が候補者一覧や履歴画面に表示される場合の扱い
- 全4種別を同時に対応可能として登録するケース（制限なし）
- 空配列（対応年代未選択）での保存試行

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ライセンス選択肢は「1級」「2級」「3級」「4級」の4つのみであること
- **FR-002**: 「S級」はライセンス選択肢に含まれてはならない
- **FR-003**: 対応年代選択肢は「第4種(U-12)」「第3種(U-15)」「第2種(U-18)」「第1種(大学・社会人)」の4種別のみであること
- **FR-004**: 「女子」「シニア」は対応年代選択肢に含まれてはならない
- **FR-005**: 審判員はライセンスを1つ選択し、対応年代を1つ以上選択しなければプロフィールを保存できない
- **FR-006**: 試合登録フォームの対象年代選択肢も同じ4種別に統一されること
- **FR-007**: 予定登録（空き登録）の年代選択肢も同じ4種別に統一されること
- **FR-008**: 既存ユーザーの旧形式データ（U12/U15/U18/Senior）は新しい種別表記（第4種(U-12)等）へ自動マイグレーションされること
- **FR-009**: 既存ユーザーの旧ライセンス値「S級」は、ユーザーが次回プロフィール編集時に正規の1〜4級から再選択できるよう案内されること

### Key Entities

- **審判ライセンス**: JFA審判資格の等級。1〜4級の4段階。審判員プロフィールに1つ紐づく
- **登録種別（対応年代）**: JFA競技会登録の種別区分。第4種(U-12)〜第1種(大学・社会人)の4種別。審判員プロフィールに1つ以上紐づく

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ライセンス選択画面に「S級」が一切表示されず、全ての審判員が正確なJFA審判ライセンス（1〜4級）のみから選択できる
- **SC-002**: 対応年代の選択肢・表示がJFA公式種別と100%一致し、旧来のU12/Senior等の表記がUI上から消える
- **SC-003**: 新規プロフィール登録・更新の操作ステップ数が変更前と同等以下（現行と同じ操作性を維持）
- **SC-004**: プロフィール登録・編集画面、候補者一覧、試合登録、空き登録の全画面で年代表記が統一される
- **SC-005**: 既存ユーザーが新しい選択体系でプロフィールを再登録する際にエラーが発生しない

## Assumptions

- 本機能の対象は地域コミュニティでの草サッカー・ユース審判であり、1級審判（J3以上）の登録も想定されるが稀なケースとして含める
- FIFA国際審判員は対象外（地域コミュニティの範囲を超えるため）
- 「女子」「シニア」種別はこのコミュニティの主要ユースケースに含まれないと判断し対象外
- データベースのライセンス値検証制約（CHECK制約）も同時に更新が必要
- 開発環境のシードデータも新しい値に更新する
- 既存データ（U12/U15/U18/Senior）は新しい種別表記へ自動マイグレーションする
- S級ライセンスの既存データは移行先がないため、該当ユーザーに次回編集時に再選択を促す
