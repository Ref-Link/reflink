# Feature Specification: Pilot Launch Preparation

**Feature Branch**: `005-pilot-launch-prep`  
**Created**: 2026-06-06  
**Status**: Draft  
**Input**: User description: "Pilot公開準備としてアイコン等の設定、利用規約、プライバシーポリシーの準備を行いたいです。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - アプリブランディング設定 (Priority: P1)

Pilot参加者（審判・運営者）がRefLinkをスマートフォンのホーム画面に追加したり、ブラウザのタブで開いたりしたとき、適切なアイコン・アプリ名・OGP画像が表示され、公式サービスとして認識できる。

**Why this priority**: アイコン・ファビコン・OGP設定はアプリの見た目の信頼性に直結し、Pilot参加者への第一印象を左右する。PWAとして追加された際のアイコン表示は特に重要。

**Independent Test**: ブラウザで `/` にアクセスしタブのファビコンを確認し、ホーム画面に追加してアイコンが正しく表示されることを確認。

**Acceptance Scenarios**:

1. **Given** アプリをブラウザで開いたとき、**When** タブを確認すると、**Then** RefLinkのファビコンが表示される
2. **Given** モバイルブラウザでアプリにアクセスしたとき、**When** ホーム画面に追加すると、**Then** RefLinkのアイコンとアプリ名「RefLink」が表示される
3. **Given** SNSやメッセージアプリでアプリURLをシェアしたとき、**When** リンクプレビューが表示されると、**Then** OGP画像・タイトル・説明文が適切に表示される

---

### User Story 2 - 利用規約ページ (Priority: P2)

新規登録ユーザー（審判・運営者）が登録前または登録中に利用規約を確認でき、サービスの使用条件・禁止事項・免責事項を把握できる。

**Why this priority**: Pilot公開においてユーザーに利用条件を明示することは、法的保護とトラブル防止のために必要。登録フローとの連携も必要。

**Independent Test**: `/terms` にアクセスして利用規約ページが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 未認証ユーザーが `/terms` にアクセスしたとき、**When** ページが読み込まれると、**Then** 利用規約の全文が表示される（認証不要）
2. **Given** ユーザーが新規登録フォームを確認しているとき、**When** 「利用規約」リンクをタップすると、**Then** 利用規約ページに遷移またはモーダル表示される
3. **Given** 利用規約ページを表示したとき、**When** スマートフォンで閲覧すると、**Then** 条文が読みやすいフォントサイズ・行間で表示される

---

### User Story 3 - プライバシーポリシーページ (Priority: P3)

ユーザーが個人情報の取り扱いについて確認でき、収集するデータの種類・利用目的・第三者提供の有無を把握できる。

**Why this priority**: 個人情報（氏名・資格情報・位置情報・LINEアカウント）を扱うサービスとして、プライバシーポリシーの開示は個人情報保護法の観点からも必須。

**Independent Test**: `/privacy` にアクセスしてプライバシーポリシーページが表示されることを確認。

**Acceptance Scenarios**:

1. **Given** 未認証ユーザーが `/privacy` にアクセスしたとき、**When** ページが読み込まれると、**Then** プライバシーポリシーの全文が表示される（認証不要）
2. **Given** 新規登録フォームを確認しているとき、**When** 「プライバシーポリシー」リンクをタップすると、**Then** プライバシーポリシーページに遷移またはモーダル表示される
3. **Given** プライバシーポリシーページを表示したとき、**When** 内容を確認すると、**Then** 収集する個人情報の種類・利用目的・第三者提供（LINE連携含む）・問い合わせ先が明記されている

---

### User Story 4 - フッターからのアクセス (Priority: P4)

アプリ内のどのページからも利用規約・プライバシーポリシーにアクセスできるよう、フッターにリンクが配置されている。

**Why this priority**: 既存ユーザーが後から規約を確認したい場合のアクセスパスを確保する。

**Independent Test**: ホーム画面・ダッシュボード等でフッターを確認し、両リンクが機能することを確認。

**Acceptance Scenarios**:

1. **Given** 認証済みユーザーがいずれかのページを表示しているとき、**When** ページ下部を確認すると、**Then** 「利用規約」「プライバシーポリシー」のリンクが表示されている
2. **Given** フッターのリンクをタップしたとき、**When** 遷移が完了すると、**Then** 対応する規約ページが表示される

---

### Edge Cases

- アイコン画像が未設定・読み込み失敗の場合、ブラウザのデフォルト表示にフォールバックされる
- 利用規約・プライバシーポリシーページはサービス変更時に更新できるよう、コンテンツ管理が容易な構造にする
- SNSシェア時にOGP画像が取得できない場合、テキストのみのプレビューにフォールバックされる

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは全ページでRefLinkのファビコン（16x16、32x32）を表示しなければならない
- **FR-002**: システムはPWAインストール時に適切なアプリアイコン（192x192、512x512）を提供しなければならない
- **FR-003**: システムはSNSシェア用のOGP画像・タイトル・説明文をメタタグとして含めなければならない
- **FR-004**: システムは `/terms` パスで利用規約ページを認証不要で公開しなければならない
- **FR-005**: システムは `/privacy` パスでプライバシーポリシーページを認証不要で公開しなければならない
- **FR-006**: 利用規約ページは以下の項目を含まなければならない：サービスの目的、利用資格、禁止事項、免責事項、規約変更について、問い合わせ先
- **FR-007**: プライバシーポリシーページは以下の項目を含まなければならない：収集する個人情報の種類、利用目的、第三者提供（LINE連携含む）、データ保管・管理、ユーザーの権利（削除・訂正）、問い合わせ先
- **FR-008**: 新規登録フォームは利用規約・プライバシーポリシーへのリンクを含めなければならない
- **FR-009**: アプリのフッターは利用規約・プライバシーポリシーへのリンクを含めなければならない
- **FR-010**: 利用規約・プライバシーポリシーページはモバイルで読みやすいレイアウトで表示されなければならない

### Key Entities

- **AppBranding**: アプリのアイコン・ファビコン・OGP画像・アプリ名・説明文
- **LegalDocument**: 利用規約またはプライバシーポリシーの文書（タイトル、条文、最終更新日）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ファビコン・PWAアイコン・OGP画像がすべての主要ブラウザ（Safari、Chrome）で正しく表示される
- **SC-002**: 利用規約・プライバシーポリシーページが未認証状態でアクセスでき、3秒以内に表示される
- **SC-003**: 新規登録フローを完了したユーザーが利用規約・プライバシーポリシーへのアクセス方法を認識できる（フォーム内リンク経由）
- **SC-004**: アプリ内のすべての主要ページからフッターの規約リンクに2タップ以内でアクセスできる
- **SC-005**: SNSでURLをシェアした際にOGPプレビュー（画像・タイトル・説明）が表示される

## Assumptions

- アイコン画像・OGP画像のデザインアセットは本フィーチャーの実装中に別途用意するか、プレースホルダーを使用してあとから差し替える
- 利用規約・プライバシーポリシーの文章はサービス運営者（ユーザー）が提供するか、Pilot段階向けの簡易版をドラフトとして作成する
- 問い合わせ先はPilot期間中は運営者のメールアドレスで対応する
- 規約の多言語対応（英語等）はPilot段階では不要で、日本語のみとする
- 既存の新規登録フォームにリンクを追加する形で実装する（フォームの構造変更は最小限）
- PWA対応はすでに `manifest.json` の基盤が存在するか、今回新たに設定する
