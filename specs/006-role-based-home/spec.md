# Feature Specification: ロールベースホーム画面

**Feature Branch**: `006-role-based-home`  
**Created**: 2026-06-07  
**Status**: Draft  
**Input**: User description: "ログイン後にユーザーのロールに応じたホーム画面を表示し、organizer/managerには管理機能へ、審判には審判機能へのエントリーポイントを提供する。兼任ユーザーには両方を表示する。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Organizerのみのユーザーがログイン後に管理画面へ到達できる (Priority: P1)

コミュニティのOrganizer（審判業務は行わない）がログイン後、管理機能（試合管理・メンバー管理）へ迷わずたどり着けるホーム画面が表示される。

**Why this priority**: 技術リテラシーの高くないPilot参加Organizerが、URLを知らなくても管理画面にたどり着けることがサービスの基本要件。現在はログイン後に `/profile`（審判UI）に飛ばされるため管理画面への導線が存在しない。

**Independent Test**: Organizerロールのアカウントでログインし、ホーム画面に「試合・メンバーを管理する」エントリーポイントが表示されてタップで管理画面に遷移することを確認。

**Acceptance Scenarios**:

1. **Given** organizer/managerロールを持つユーザーがログインしたとき、**When** ホーム画面が表示されると、**Then** 管理機能へのエントリーポイント（試合管理・メンバー管理）が表示される
2. **Given** 管理エントリーポイントをタップしたとき、**When** 遷移が完了すると、**Then** `/admin/matches` が表示される
3. **Given** refereeロールのみを持つユーザーがログインしたとき、**When** ホーム画面が表示されると、**Then** 管理エントリーポイントは表示されない

---

### User Story 2 - 兼任ユーザーが管理機能と審判機能の両方にアクセスできる (Priority: P1)

Organizerとして試合を管理しつつ、自身も審判として出場する兼任ユーザーが、ホーム画面から両機能へ迷わずアクセスできる。

**Why this priority**: Pilot参加者の多くは兼任が想定される。どちらかにしかアクセスできないと業務が成立しない。

**Independent Test**: organizer + referee両ロールを持つアカウントでログインし、ホーム画面に管理エントリーポイントと審判エントリーポイントの両方が表示されることを確認。

**Acceptance Scenarios**:

1. **Given** organizer/managerロールかつ審判プロフィールを持つユーザーがログインしたとき、**When** ホーム画面が表示されると、**Then** 管理エントリーポイントと審判エントリーポイントの両方が表示される
2. **Given** 審判エントリーポイントをタップしたとき、**When** 遷移が完了すると、**Then** 空き日程・担当履歴など審判機能にアクセスできる
3. **Given** 管理画面から戻りたいとき、**When** ホームに戻ると、**Then** 再び両方のエントリーポイントが表示される

---

### User Story 3 - 審判のみのユーザーのログイン後体験が維持される (Priority: P2)

コミュニティへの参加申請中または承認済みの審判ユーザーが、これまでと同様にプロフィール・空き日程・担当履歴にアクセスできる。既存の審判UXを壊さない。

**Why this priority**: 既存機能の回帰を防ぐ。審判ユーザーの方がOrganizerより人数が多い。

**Independent Test**: refereeロールのみのアカウントでログインし、従来通りプロフィール・空き日程・担当履歴が使えることを確認。

**Acceptance Scenarios**:

1. **Given** refereeロールのみを持つユーザーがログインしたとき、**When** ホーム画面が表示されると、**Then** 審判機能（プロフィール・空き日程・担当履歴）へのエントリーポイントが表示される
2. **Given** コミュニティ未参加（参加申請前）のユーザーがログインしたとき、**When** ホーム画面が表示されると、**Then** コミュニティ参加を促すエントリーポイントが表示される
3. **Given** 審判エントリーポイントからbottom navを利用しているとき、**When** プロフィール・空き日程・担当履歴を切り替えると、**Then** 従来と同じ操作感で遷移できる

---

### Edge Cases

- organizer/managerロールは持っているが、承認済み（approved）でない場合は管理エントリーポイントを表示しない
- 複数コミュニティでorganizerロールを持つ場合、管理画面では最初に見つかったコミュニティが表示される（Pilot期間の既知の制限）
- ユーザーがコミュニティに属していない（登録直後）場合は、コミュニティ参加案内を表示する
- ログアウト後に再ログインした際も、ロールに応じた同じホーム画面が表示される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはログイン後に `/` でロール判定を行い、適切なホーム画面を表示しなければならない（現在の即時リダイレクトを廃止）
- **FR-002**: システムはいずれかのコミュニティでorganizer/managerロールを持ちかつapprovedであるユーザーに、管理機能エントリーポイントを表示しなければならない
- **FR-003**: システムはrefereeとして参加中または参加申請中のユーザーに、審判機能エントリーポイントを表示しなければならない
- **FR-004**: 兼任ユーザー（organizer + referee）には管理エントリーポイントと審判エントリーポイントの両方を表示しなければならない
- **FR-005**: 管理エントリーポイントから `/admin/matches` へ遷移できなければならない
- **FR-006**: 審判エントリーポイントから審判機能（プロフィール・空き日程・担当履歴）へ遷移できなければならない
- **FR-007**: コミュニティ未参加ユーザーにはコミュニティ参加（`/join`）へのエントリーポイントを表示しなければならない
- **FR-008**: ホーム画面はモバイルで直感的に操作できるタップターゲットサイズで表示されなければならない
- **FR-009**: 管理画面・審判画面からホーム画面（`/`）に戻れるナビゲーションが存在しなければならない

### Key Entities

- **UserRoleContext**: ユーザーのコミュニティメンバーシップ（role: organizer/manager/referee、status: approved/pending）
- **HomeEntry**: ホーム画面に表示するエントリーポイント（ラベル・遷移先・表示条件）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: organizerロールのユーザーがログイン後、何もURLを知らずに管理画面に到達できる（タップ1回以内）
- **SC-002**: 兼任ユーザーがホーム画面から管理機能・審判機能どちらにも2タップ以内でアクセスできる
- **SC-003**: 既存の審判ユーザーのログイン後体験に変化がなく、既存機能が引き続き動作する
- **SC-004**: ホーム画面のエントリーポイントが、スマートフォンで片手操作できるサイズで表示される

## Assumptions

- Pilot期間中、1ユーザーが複数コミュニティでorganizerを兼任するケースは想定しない（limit(1)の現行動作で対応）
- コミュニティ参加申請中（pending）のユーザーは審判機能エントリーポイントを表示するが、空き日程・担当履歴は承認後のみ利用可能（既存の挙動を維持）
- ホーム画面のデザインはRefLinkの既存スタイル（Tailwind CSS）に準拠する
- 管理画面（`/admin`）・審判機能（`/(referee)`）の内部ナビゲーション構造は変更しない
- ユーザー名の表示は `users.display_name` から取得する
