# Feature Specification: UX改善（審判・運営者）

**Feature Branch**: `010-ux-improvements`  
**Created**: 2026-06-10  
**Status**: Draft  
**Input**: User description: "これまで議論してきた方針でUX改善を行います。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 空き日程登録時の対応年代を自動プリセット (Priority: P1)

審判がプロフィールで設定した対応年代が、空き日程追加フォームの初期値として反映される。毎回同じ年代を手動で選び直す手間がなくなる。

**Why this priority**: 空き日程登録は審判が最も頻繁に行う操作であり、毎回の選び直しコストが大きい。

**Independent Test**: プロフィールに U15・U18 を設定した審判が空き日程追加フォームを開くと、U15・U18 がすでに選択済みになっていることを確認できる。

**Acceptance Scenarios**:

1. **Given** プロフィールに対応年代 `U15, U18` を登録済みの審判が、**When** 空き日程追加フォームを開いた場合、**Then** U15 と U18 のボタンが選択済み状態で表示される。
2. **Given** 審判が空き日程を追加して登録に成功した場合、**When** フォームがリセットされた後も、**Then** プロフィールの対応年代が再度プリセットされている。

---

### User Story 2 - 空き日程フォームから備考欄を削除 (Priority: P2)

実際には使用されていない備考欄をフォームから取り除くことで、フォームをシンプルにする。

**Why this priority**: 使われない入力欄はフォームのノイズになりユーザーを迷わせる。

**Independent Test**: 空き日程追加フォームを開いて備考欄（テキストエリア）が存在しないことを確認できる。

**Acceptance Scenarios**:

1. **Given** 審判が空き日程追加フォームを開いた場合、**When** フォームを確認した場合、**Then** 備考のテキストエリアが表示されない。
2. **Given** 過去に備考付きで登録された空き日程がある場合、**When** 登録済み一覧を確認した場合、**Then** 既存の備考テキストは引き続き表示される（後方互換）。

---

### User Story 3 - 担当履歴から試合詳細をタップ展開で確認 (Priority: P2)

担当履歴の試合一覧で各アイテムをタップすると、報酬・必要人数・備考などの詳細情報が展開表示される。

**Why this priority**: 過去の試合情報（報酬等）を参照したい審判が多く、現状では確認手段がない。

**Independent Test**: 担当履歴リストの任意の試合をタップして詳細セクションが展開されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 確定済み担当履歴が存在する審判が、**When** 履歴リストの試合をタップした場合、**Then** 必要審判人数・報酬（設定時）・備考（設定時）が展開表示される。
2. **Given** 詳細が展開されている試合がある場合、**When** 再度タップした場合、**Then** 詳細が折り畳まれる。
3. **Given** 報酬・備考が未設定の試合の場合、**When** 詳細を展開した場合、**Then** 該当項目は表示されない（非表示）。

---

### User Story 4 - 試合一覧・詳細で確定済み審判人数を即時確認 (Priority: P1)

運営者が試合一覧および試合詳細画面で、必要審判人数のうち何名が確定済みかを一目で確認できる。

**Why this priority**: 審判確保状況の把握は運営者が最も頻繁に必要とする情報であり、現状では別画面（アサイン状況）に遷移しないとわからない。

**Independent Test**: 試合一覧で各試合カードに「主審 1/1名確定」「副審 0/2名確定」のような表示があることを確認できる。

**Acceptance Scenarios**:

1. **Given** 主審 1 名確定・副審 1 名未確定の試合が存在する場合、**When** 試合一覧を表示した場合、**Then** 「主審 1/1名」「副審 0/2名」のような確定数／必要数の表示がある。
2. **Given** 同じ試合の詳細ページを表示した場合、**When** 必要人数セクションを確認した場合、**Then** 同様に確定数／必要数が表示される。

---

### User Story 5 - 必要人数が揃ったら試合ステータスを自動で「確定済」へ (Priority: P1)

運営者がアサインを確定した結果として必要人数がすべて埋まった場合、試合ステータスが自動的に「募集中」から「確定済」へ変わる。

**Why this priority**: 手動でステータスを変更する操作が存在しないため、現状では満員になっても「募集中」のままになり続ける。

**Independent Test**: 必要人数（主審 1 名・副審 2 名）の最後の 1 名を確定した直後に試合ステータスが「確定済」になることを確認できる。

**Acceptance Scenarios**:

1. **Given** 必要人数の最後のアサインを確定した場合、**When** 試合一覧または試合詳細を表示した場合、**Then** 試合ステータスが「確定済」になっている。
2. **Given** 主審 1 名は確定済みだが副審がまだの場合、**When** 試合一覧を表示した場合、**Then** ステータスは「募集中」のままである。

---

### User Story 6 - 審判候補一覧・メンバー一覧からプロフィール詳細をタップ展開で確認 (Priority: P2)

運営者が審判候補一覧またはメンバー管理画面で各審判をタップすると、対応年代・担当可能役割・移動範囲などのプロフィール詳細が展開表示される。（氏名・連絡先・real_name は除く）

**Why this priority**: 候補選定・メンバー承認時に審判のスキル情報を確認したい運営者のニーズがある。

**Independent Test**: 審判候補一覧で任意の候補をタップして対応年代・役割・移動範囲が展開されることを確認できる。

**Acceptance Scenarios**:

1. **Given** 審判候補一覧に候補が存在する場合、**When** 候補をタップした場合、**Then** ライセンス・対応年代・担当役割・地域・移動範囲が展開表示される。
2. **Given** メンバー管理画面でメンバーが存在する場合、**When** メンバーをタップした場合、**Then** ライセンス・対応年代・担当役割・移動範囲が展開表示される。
3. **Given** 展開されているアイテムがある場合、**When** 別のアイテムをタップした場合、**Then** 前のアイテムが折り畳まれ、新しいアイテムが展開される（1 件のみ展開）。
4. **Given** どのアイテムでも、**When** 展開した場合でも、**Then** 氏名（real_name）・電話番号は表示されない。

---

### Edge Cases

- 対応年代が未設定のプロフィールで空き日程フォームを開いた場合、年代ボタンは全て未選択状態になる。
- 備考が空文字の既存空き日程では、備考行自体を表示しない。
- 報酬 0 円（`0`）は「無償」などとして表示する（`null` と区別する）。
- 試合の必要人数が 0 の役割（例：副審 0 名）は確定数表示の対象外とする。
- メンバー管理で移動範囲未設定（`null`）のメンバーは移動範囲行を非表示にする。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 空き日程追加フォームは、ログインユーザーのプロフィールに登録された対応年代を初期選択状態で表示しなければならない。
- **FR-002**: 空き日程追加フォームには備考入力欄を表示しない。
- **FR-003**: 担当履歴の各試合アイテムはタップにより展開し、必要審判人数・報酬（設定時）・試合備考（設定時）を表示しなければならない。
- **FR-004**: 試合一覧の各カードに、役割ごとの「確定数 / 必要数」を表示しなければならない。
- **FR-005**: 試合詳細画面の人数表示に、役割ごとの「確定数 / 必要数」を表示しなければならない。
- **FR-006**: アサイン確定操作の結果として必要人数がすべて充足された場合、試合ステータスを自動的に「確定済」へ更新しなければならない。
- **FR-007**: 審判候補一覧の各候補はタップにより展開し、ライセンス・対応年代・担当役割・地域・移動範囲（設定時）を表示しなければならない。
- **FR-008**: メンバー管理（承認待ち・承認済み）の各メンバーはタップにより展開し、ライセンス・対応年代・担当役割・移動範囲（設定時）を表示しなければならない。
- **FR-009**: タップ展開は同時に 1 件のみ展開し、別アイテムをタップした場合は前のアイテムを自動で折り畳む。
- **FR-010**: real_name および電話番号は、確定アサイン済みの運営者連絡先開示フロー以外では表示しない。

### Key Entities

- **空き日程フォーム**: 審判が対応可能日を登録するフォーム。対応年代・日付・時刻を持つ。
- **担当履歴アイテム**: 審判の確定済みアサイン。試合情報（タイトル・日時・会場・年代・報酬・備考・必要人数）を含む。
- **試合カード（一覧）**: 運営者向け試合一覧の各エントリ。確定数／必要数を含む。
- **審判候補**: 試合詳細ページに表示されるアサイン候補。プロフィール詳細を展開表示できる。
- **コミュニティメンバー**: メンバー管理画面に表示される審判。プロフィール詳細を展開表示できる。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: プロフィールに対応年代を設定済みの審判は、空き日程フォームで対応年代を選び直すことなく登録できる。
- **SC-002**: 空き日程追加フォームのフィールド数が現行より 1 つ（備考欄）削減される。
- **SC-003**: 担当履歴の試合詳細（報酬・必要人数・備考）を 1 タップ以内に確認できる。
- **SC-004**: 試合一覧・詳細画面で各役割の確定数と必要数が同一画面内で確認できる。
- **SC-005**: 最後のアサインを確定した直後に試合ステータスが「確定済」へ自動更新される（手動操作不要）。
- **SC-006**: 審判候補・メンバー一覧からプロフィール詳細（年代・役割・移動範囲）を 1 タップ以内に確認できる。

## Assumptions

- 既存のプロフィール API（`GET /api/profile`）はすでに `age_groups` を返しており、空き日程ページから呼び出せる。
- 試合の確定人数はアサインテーブルから `role × status='confirmed'` でリアルタイムに集計できる。
- 試合ステータスの自動更新はアサイン確定 API 呼び出し時のサーバーサイド処理として実装する。
- メンバー API の SELECT フィールドを拡張するだけでよく、テーブルスキーマの変更は不要。
- 担当履歴 API の SELECT に `referees_needed`, `assistants_needed`, `compensation`, `notes` を追加するだけでよく、スキーマ変更は不要。
- 備考欄のデータモデル（`notes` カラム）は削除せず、フォーム UI からのみ除去する。
- 既存のタップ展開 UI パターンは本プロジェクトで確立済みであるため、同一パターンを適用する。
