# Quickstart: 審判確定人数の上限チェック

**Branch**: `015-referee-count-limit` | **Date**: 2026-06-11

## テスト手順

### 前提条件

- 管理者アカウントでログイン済み
- 主審1名・副審0名を募集している試合が存在する
- その試合に複数の審判候補（`accepted` 状態）がいる

### シナリオ1: 上限超過が拒否される（P1）

1. アサイン状況ページを開く（`/admin/matches/[id]/assignments`）
2. 主審候補1人目の「確定」ボタンを押す → 確定成功（「アサインを確定しました」と表示）
3. 主審候補2人目の「確定」ボタンを押す（まだ `accepted` 状態の場合）
   - **期待**: エラーメッセージ「主審の確定人数が募集人数に達しています」が表示され、確定されない

### シナリオ2: ボタンの非活性化（P2）

1. 上記シナリオ1の手順1〜2を実施して主審1名を確定
2. 候補一覧を確認
   - **期待**: 残りの `accepted` 状態の主審候補の「確定」ボタンが非活性（グレーアウト）になっている
3. 副審候補がいる場合、副審の「確定」ボタンは活性のまま（独立していることを確認）

### シナリオ3: 正常ケースのリグレッション確認

1. 主審2名・副審2名を募集する試合を用意
2. 主審1名目を確定 → 成功
3. 主審2名目を確定 → 成功
4. 副審1名目を確定 → 成功
5. 副審2名目を確定 → 成功
6. 主審3名目を確定しようとする → 失敗（上限チェック）

### シナリオ4: APIレベルの直接テスト（任意）

```bash
# 上限に達した後に PATCH を直接叩く
curl -X PATCH https://<host>/api/matches/<matchId>/assignments/<assignmentId>/confirm \
  -H "Cookie: <session>" \
  -w "\nStatus: %{http_code}\n"

# 期待: HTTP 409, {"error":"SLOT_FULL","message":"..."}
```
