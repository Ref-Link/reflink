# Feature Specification: 審判確定人数の上限チェック

**Feature Branch**: `015-referee-count-limit`  
**Created**: 2026-06-11  
**Status**: Draft  
**Input**: 試合の主審・副審の募集人数以上の審判員を確定できないようにチェックする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 募集人数を超えた審判確定の防止 (Priority: P1)

試合の主審・副審それぞれについて、確定済み人数が募集人数に達している場合、それ以上の審判員を確定しようとするとエラーになり、処理が止まる。

**Why this priority**: スクリーンショットが示すように、現状では募集1名に対して2名を確定できてしまう。過剰確定は審判員への誤通知・二重手配につながるため最優先で防ぐべき。

**Independent Test**: 募集1名の試合で1名確定済みの状態で、2人目の確定操作を試みると失敗することを確認。

**Acceptance Scenarios**:

1. **Given** 主審1名募集の試合で主審が1名確定済み、**When** 管理者がさらに別の主審候補を確定しようとする、**Then** エラーが返り確定は行われない
2. **Given** 副審2名募集の試合で副審が2名確定済み、**When** 管理者が3人目の副審を確定しようとする、**Then** エラーが返り確定は行われない
3. **Given** 主審1名募集の試合で主審が未確定（0名）、**When** 管理者が主審候補を1名確定する、**Then** 確定が成功し確定済みステータスになる
4. **Given** 主審・副審ともに募集人数未満の試合、**When** それぞれの枠内で確定操作する、**Then** 正常に確定できる

---

### User Story 2 - 管理画面での確定可否の視覚的フィードバック (Priority: P2)

管理者が審判候補一覧を見たとき、すでに募集人数が埋まっているロールの確定ボタンが非活性または非表示になっており、操作前に気づける。

**Why this priority**: P1のAPIエラーだけでは「なぜ確定できないか」が画面上で分からない。UX向上としてボタン制御も行う。P1完了後に対応する。

**Independent Test**: 募集1名の試合で主審を1名確定済みにした後、残りの主審候補の確定ボタンが非活性になっていることを目視確認。

**Acceptance Scenarios**:

1. **Given** 主審1名募集の試合で主審が1名確定済み、**When** 管理者が審判候補一覧を表示する、**Then** 残りの主審候補の確定ボタンが非活性状態で表示される
2. **Given** 副審の枠が埋まっていない試合、**When** 管理者が審判候補一覧を表示する、**Then** 副審候補の確定ボタンは活性状態のまま
3. **Given** 全ロールの枠が埋まった試合（確定済み）、**When** 管理者が審判候補一覧を表示する、**Then** すべての確定ボタンが非活性状態で表示される

---

### Edge Cases

- 主審の枠が埋まっていても副審の枠が空いている場合、副審の確定は引き続き可能
- 確定済みの審判が後から取り消し（キャンセル）された場合、再び枠が空いて確定できるようになる（取り消し機能は既存の動作に依存）
- 募集人数が0の場合、そのロールへの確定は常に拒否される

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: アサイン確定操作時に、対象ロール（主審／副審）の確定済み人数が募集人数以上であればエラーを返し、確定を拒否する
- **FR-002**: エラーレスポンスは確定が拒否された理由（募集人数の超過）を示すメッセージを含む
- **FR-003**: 管理画面の審判候補一覧において、対象ロールの確定済み人数が募集人数に達している場合、確定ボタンを非活性にする
- **FR-004**: 既存の確定済みアサインへの重複確定チェック（`status === 'confirmed'` のエラー）は引き続き機能する
- **FR-005**: 主審（referee）と副審（assistant_referee）のカウントは独立して管理し、一方の上限超過が他方の確定操作に影響しない

### Key Entities

- **試合（Match）**: `referees_needed`（主審募集人数）、`assistants_needed`（副審募集人数）を保持
- **アサイン（Assignment）**: `role`（referee / assistant_referee）、`status`（pending / accepted / confirmed / cancelled）を保持

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 募集人数に達している状態での確定操作が100%拒否される（誤確定ゼロ）
- **SC-002**: 募集人数未満の状態での正当な確定操作が引き続き成功する（既存機能リグレッションゼロ）
- **SC-003**: 管理者が候補一覧を見た時点で確定可否をボタンの状態から即座に判断できる（追加操作なし）
- **SC-004**: 超過確定試行時のエラーメッセージから管理者が原因を理解できる

## Assumptions

- アサインの `role` フィールドは `referee`（主審）または `assistant_referee`（副審）のいずれかであり、それ以外の値は存在しない
- 確定済み人数のカウントは `status = 'confirmed'` のアサインのみを対象とする（`accepted` や `pending` は含まない）
- アサイン取り消し機能は既存の実装に依存し、本機能では新たに実装しない
- バックエンドのチェック（FR-001）を必須とし、フロントエンドのボタン制御（FR-003）はそれに加えた追加の防護とする
